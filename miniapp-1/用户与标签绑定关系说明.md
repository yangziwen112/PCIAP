# 用户与标签绑定关系说明

## 📚 概述

用户与标签的绑定关系是通过 **subscriptions（订阅）** 集合实现的，建立了用户与其关注标签的一对多关系。用户通过关注标签，可以获取对应标签的内容推荐，实现个性化内容过滤。

## 🔗 绑定机制详解

### 绑定方式：基于 userId 的唯一性

```javascript
// subscriptions 集合上的唯一索引
{
  userId: 1,  // 唯一索引 - 每个用户只能有一条订阅记录
  name: 'uk_sub_user'
}

// 实际代码（miniapp-backend/src/db.js）
await db.collection('subscriptions').createIndex({ 
  userId: 1 
}, { 
  unique: true, 
  name: 'uk_sub_user' 
});
```

**关键特点**：
- ✅ 每个用户只有 **一条** 订阅记录
- ✅ 该记录中的 `tagIds` 数组存储用户关注的所有标签ID
- ✅ 通过 `userId` 字段与 `users` 集合关联
- ✅ 支持灵活的标签组合（一对多）

### 数据绑定流程

```
1️⃣  用户登录
    │
    ├─ 输入账号、密码、身份
    ├─ 云函数验证 users 集合
    ├─ 返回 userId（_id）
    ▼

2️⃣  保存登录状态
    │
    ├─ 存储 userId 到本地 Storage
    ├─ 存储用户信息到 app.globalData
    ▼

3️⃣  进入订阅页面
    │
    ├─ 获取所有标签（meta/tags）
    ├─ 根据 userId 查询订阅数据（user/subscribe/get）
    │   └─ SELECT * FROM subscriptions WHERE userId = 'xxx'
    ├─ 获取该用户的 tagIds 列表
    ├─ 标记哪些标签已关注
    ▼

4️⃣  用户关注/取消关注标签
    │
    ├─ 前端更新本地状态
    ├─ 重新组织 tagIds 数组
    ├─ 调用 user/subscribe/set 接口
    │   └─ UPDATE subscriptions 
    │      SET tagIds = ['tag_1', 'tag_2']
    │      WHERE userId = 'xxx'
    ├─ 数据保存到数据库
    ▼

5️⃣  退出登录
    │
    ├─ 清除本地 Storage
    ├─ 清除全局状态
    ├─ subscriptions 中的数据保留
    ▼

6️⃣  重新登录同一账号
    │
    ├─ 获取用户信息（新的 userId）
    ├─ 查询 subscriptions（WHERE userId = ...）
    ├─ ✅ 恢复之前的 tagIds 列表
    ▼

7️⃣  切换不同账号
    │
    └─ 查询不同的 subscriptions 记录
       tagIds 数据各自独立
```

## 💾 前后端实现

### 前端（小程序）

#### 数据获取 - `pages/subscription/index.js`

```javascript
// 1. 获取所有标签和用户订阅
const [tagsRes, subsRes] = await Promise.all([
  callApi('meta/tags', {}),
  callApi('user/subscribe/get', { userId })
])

const allTagsList = tagsRes.list || []
const followedTagIds = subsRes.tagIds || []  // 用户已关注的标签ID数组

// 2. 为标签添加关注状态
const allTags = allTagsList.map(tag => ({
  ...tag,
  followed: followedTagIds.includes(tag._id)  // 判断用户是否关注
}))

// 3. 筛选已关注的标签
const followedTags = allTags.filter(tag => tag.followed)
```

#### 数据保存 - `pages/subscription/index.js`

```javascript
// 切换标签关注状态
async onToggleTag(e) {
  const id = e.currentTarget.dataset.id
  
  // 更新本地 tagIds 数组
  const followedTags = allTags.filter(tag => tag.followed)
  const followedTagIds = followedTags.map(tag => tag._id)
  
  // 发送到服务器
  await callApi('user/subscribe/set', { 
    userId: this.data.userId,
    tagIds: followedTagIds  // 新的标签ID列表
  })
}
```

### 后端（云函数）

#### 获取订阅 - `cloudfunctions/api/index.js`

```javascript
async function getSubscription({ userId }) {
  try {
    // 根据 userId 查询该用户的订阅记录
    const res = await db.collection('subscriptions')
      .where({ userId })
      .get()
    
    // 返回用户的标签列表
    const doc = (res.data || [])[0] || { sourceIds: [], tagIds: [] }
    return doc
  } catch (error) {
    return { sourceIds: [], tagIds: [] }
  }
}
```

#### 保存订阅 - `cloudfunctions/api/index.js`

```javascript
async function setSubscription({ userId, sourceIds, tagIds }) {
  try {
    const coll = db.collection('subscriptions')
    
    // 查询用户是否已有订阅记录
    const res = await coll.where({ userId }).get()
    const existing = (res.data || [])[0] || {}
    
    // 准备更新数据
    const updateData = {
      userId,
      sourceIds: Array.isArray(sourceIds) ? sourceIds : (existing.sourceIds || []),
      tagIds: Array.isArray(tagIds) ? tagIds : (existing.tagIds || [])
    }
    
    // 如果记录存在则更新，否则创建新记录
    if ((res.data || []).length) {
      await coll.where({ userId }).update({ data: updateData })
    } else {
      await coll.add({ data: updateData })
    }
    
    return { ok: true }
  } catch (error) {
    return { error: '设置失败' }
  }
}
```

## 🎯 关键特性

### 1. 数据隔离
- 每个用户有独立的 `subscriptions` 记录
- 用户A的标签选择不影响用户B
- 通过 `userId` 字段完全隔离

### 2. 数据持久化
- ✅ 退出登录：subscriptions 数据保存在数据库中
- ✅ 重新登录：根据 userId 自动恢复订阅
- ✅ 永久保存：除非明确删除，否则数据永久保存

### 3. 灵活的标签组合
- 一个用户可以关注多个标签（`tagIds` 数组）
- 支持动态添加/删除标签
- 无最大数量限制

### 4. 实时同步
- 前端修改立即更新数据库
- 用户体验流畅（Optimistic UI Update）
- 失败时自动回滚

## 🔍 场景示例

### 场景1：用户关注标签
```
用户：23012774
操作：关注"竞赛"、"讲座"两个标签

数据库变化：
subscriptions 集合
{
  userId: "623f4a5c8d9e2f1a4b5c6d7e",
  tagIds: ["tag_竞赛", "tag_讲座"],
  updatedAt: 1697811234
}

查询结果：
- ✅ 竞赛标签 - 显示为"已关注"
- ✅ 讲座标签 - 显示为"已关注"
- ❌ 其他标签 - 显示为"关注"
```

### 场景2：用户退出登录再登录
```
步骤1：用户 A (23012774) 关注了"竞赛"标签
subscriptions: { userId: A_ID, tagIds: ["tag_竞赛"] }

步骤2：点击退出登录
- 本地 Storage 清空
- app.globalData.user 清空
- subscriptions 记录保留在数据库

步骤3：重新登录用户 A
- 获取 userId（同一个用户，ID相同）
- 查询 subscriptions WHERE userId = A_ID
- 返回 tagIds: ["tag_竞赛"]
- ✅ 恢复之前关注的标签

步骤4：如果登录用户 B (admin001)
- 获取不同的 userId
- 查询 subscriptions WHERE userId = B_ID
- 返回用户B自己的标签列表（可能为空）
```

### 场景3：多用户独立使用
```
用户A的订阅：
{ userId: "A_ID", tagIds: ["tag_竞赛", "tag_讲座"] }

用户B的订阅：
{ userId: "B_ID", tagIds: ["tag_招聘"] }

用户C的订阅：
{ userId: "C_ID", tagIds: [] }  # 未关注任何标签

➡️ 每个用户的数据完全独立，互不影响
```

## 🛠️ 数据库查询示例

### MongoDB 查询语句

```javascript
// 1. 查询用户 A 关注的所有标签
db.collection('subscriptions').where({ 
  userId: "623f4a5c8d9e2f1a4b5c6d7e" 
}).get()

// 2. 查询所有有订阅的用户
db.collection('subscriptions').where({
  tagIds: db.command.exists(true)
}).get()

// 3. 查询某个标签被多少用户关注
db.collection('subscriptions').where({
  tagIds: db.command.in(["tag_竞赛"])
}).count()

// 4. 添加新的关注
db.collection('subscriptions').where({
  userId: "623f4a5c8d9e2f1a4b5c6d7e"
}).update({
  data: {
    tagIds: db.command.push(["tag_新标签"])
  }
})

// 5. 清除所有订阅
db.collection('subscriptions').where({
  userId: "623f4a5c8d9e2f1a4b5c6d7e"
}).update({
  data: {
    tagIds: []
  }
})
```

## 🔐 安全性设计

### 1. 用户隔离
- 通过 `userId` 确保用户只能访问自己的订阅
- 云函数从上下文获取 `ctx.OPENID`，防止伪造

### 2. 权限验证
```javascript
// 云函数中获取真实用户ID
const userId = ctx.OPENID || 'demo-user'

// 只更新自己的数据
await db.collection('subscriptions').where({ 
  userId: userId  // 使用系统自动获取的ID
}).update({ data: updateData })
```

### 3. 数据一致性
- 唯一索引保证每个用户只有一条记录
- Upsert 操作确保数据完整性

## 📝 总结

**用户与标签的绑定关系是通过 `subscriptions` 集合实现的：**

| 维度 | 说明 |
|------|------|
| **绑定方式** | 基于 `userId` 的一对多关系 |
| **数据位置** | `subscriptions.tagIds` 数组 |
| **唯一性** | 每个用户一条记录（唯一索引） |
| **隔离性** | 用户数据完全独立 |
| **持久化** | 永久保存，登录时自动恢复 |
| **灵活性** | 支持任意数量的标签组合 |
| **实时性** | 修改立即同步到数据库 |

这种设计既保证了数据安全隔离，又提供了灵活的标签组合能力，是校园活动平台个性化推荐的基础。
