# PCIAP UI 与交互规格

## 1. 产品原则

PCIAP 面向需要快速获得校园可靠信息的学生。界面优先帮助用户完成“找到信息、判断是否可信、知道下一步”三件事，而不是展示尽可能多的功能。

## 2. 基础设计令牌

| 类型 | 约束 |
| --- | --- |
| 主色 | 用于主按钮、当前 Tab 和关键链接；同一页面只保留一个主色层级 |
| 表面色 | 页面背景、卡片背景和弹层背景分层，避免所有内容都使用纯白卡片 |
| 文字色 | 标题、正文、辅助信息使用明确的三级层级 |
| 间距 | 以 8 为基础单位，页面边距、卡片内边距和区块间距统一 |
| 圆角 | 卡片和输入框使用中等圆角，按钮不使用过度胶囊化装饰 |
| 状态色 | 成功、提醒、错误分别表达状态，不只依靠颜色，必须配合文字 |

## 3. 页面结构

### 首页

顶部只保留页面标题和登录状态；首屏突出搜索/AI 问答和一组高价值资讯。推荐、分类和活动入口采用分组布局，避免十几个并排按钮争夺注意力。

### AI 助手

输入框是唯一主操作。示例问题使用可点击的短句；回答下方展示来源和状态。回答加载时使用一条连续的状态提示，不同时显示多个旋转图标。

### 资讯详情

标题、来源、发布时间和正文顺序固定。原文链接、收藏和分享放在底部操作区；来源缺失时明确提示“暂无可核验来源”。

### 校园墙

信息流与发布功能分离。列表卡片突出作者、时间和正文摘要；发布页按“内容—分类—图片—提交”顺序组织，表单错误就地显示。

### 个人中心与设置

四个页面统一使用 `displayName`，头像、昵称和账号信息来自同一用户对象。设置页只展示当前账号能改变的选项，不重复显示登录、注册和账号身份按钮。

## 4. 异步状态协议

| 状态 | 用户看到的内容 | 可用操作 |
| --- | --- | --- |
| loading | 轻量占位和当前任务说明 | 返回或取消 |
| ready | 真实数据和来源 | 查看、收藏、继续 |
| empty | 没有匹配内容的原因 | 修改关键词、查看全部 |
| error | 接口或数据源失败原因 | 重新加载、稍后重试 |
| forbidden | 当前账号无权限 | 去登录或返回 |
| AI grounded | 回答、证据数量、来源 | 查看原文 |
| AI no_match | 未找到可靠证据 | 缩小范围、补充条件 |
| AI unavailable | 数据库/模型暂不可用 | 重试，不展示猜测结论 |

## 5. 统一用户信息规则

用户展示名优先级为：`displayName → nickname → userName → username → 用户`。后端响应应同时返回 `displayName`，前端不再根据页面自行猜字段。消息列表、聊天标题、聊天气泡、校园墙作者、评论作者、好友信息和个人中心均必须使用同一规则。

## 6. 关键交互验收

- 每个页面只有一个主按钮，主按钮文案描述动作和结果。
- 连续点击不会产生重复请求；请求进行中按钮进入禁用或 loading 状态。
- 登录失效时保留用户当前意图，登录后返回原页面。
- 数据为空时不使用模拟卡片填充。
- 失败提示说明原因，并提供明确恢复动作。
- AI 无证据时禁止生成具体日期、政策和通知结论。
- 个人数据和管理员数据由服务端校验，前端隐藏不能作为安全边界。

## 7. 回归测试方向

1. 使用不同字段组合创建用户，验证四个页面显示名完全一致。
2. 用户发送和接收消息后，验证消息列表、聊天页标题和气泡名称一致。
3. 知识库内容仅把关键词放在 `description`、`actionItem` 或 `sourceName` 时，验证仍能命中。
4. 知识库无结果、查询失败、全部内容过期时，验证 UI 分别显示无匹配、不可用和无有效内容。
5. 快速连续点击发送、刷新和发布，验证不会重复写入。
6. 游客、普通用户和管理员分别验证页面入口、云函数权限和错误提示。
