# unibestX UI 设计沉淀

> 本文是 PCIAP 对 `cq112233/unibestX` 的设计方法总结，不复制其代码、图片或业务资源。

## 1. 参考范围

- 项目：<https://github.com/cq112233/unibestX>
- 重点阅读：项目说明、架构指南、功能指南、主题变量、全局样式、TabBar、路由守卫和 Agent 约束文档。
- 适用范围：PCIAP 微信小程序的信息流、资讯详情、AI 助手、校园墙、个人中心和设置页。

## 2. 值得复用的方法

### 单一主题源

颜色、圆角、间距、阴影和字号必须先在主题层定义，再被页面和组件引用。页面不再各自维护一套蓝色、灰色和边距，避免同一产品出现“像四个小程序”的问题。

### 页面与组件分工

页面负责取数、权限和页面状态；组件负责展示和局部交互。列表卡片、空状态、错误提示、加载占位和底部操作区使用统一组件，减少重复逻辑和视觉漂移。

### 状态先于装饰

每个异步页面至少定义 `loading`、`ready`、`empty`、`error` 四种状态。AI 页面还要区分 `grounded`、`no_match`、`unavailable` 和 `reviewing`，不把失败状态伪装成正常内容。

### 导航与安全区统一

顶部导航、页面安全区、底部 TabBar 和滚动区域由统一布局约束管理。页面内部只描述内容，不重复计算顶部间距，避免不同页面标题位置跳动。

### 路由、权限、UI 状态分层

路由守卫只判断能否进入；页面状态判断当前是否加载完成；服务端权限决定数据能否读取或写入。不能用“隐藏按钮”代替权限控制，也不能把登录态直接等同于管理员权限。

### 规格驱动交付

先写页面目标、关键任务、状态流转和验收条件，再实施 WXML、WXSS 和 JS。每次改版必须能够回答：用户进入页面要完成什么、主按钮是什么、失败后如何恢复。

## 3. PCIAP 的落地规则

1. 首页只保留一个主任务入口，其余功能通过分组卡片或二级页面承载。
2. 资讯卡片只突出标题、来源、时间和下一步，不堆叠装饰标签。
3. AI 助手首屏展示“能查什么”和最近问题，不展示内部 Agent 名称。
4. 个人信息统一调用 `utils/user-display.js` 的 `displayName`，禁止页面自行在 `nickname`、`username`、`userName` 之间选择。
5. 所有按钮使用动作型文案，例如“查看原文”“重新加载”“去登录”，避免“确定”“操作”等无上下文文字。
6. 弹窗只用于确认、权限和不可逆操作；普通提示使用轻量 Toast 或页面内状态。
7. 对数据未返回、数据过期和接口失败分别说明，不使用演示数据填充真实用户页面。

## 4. Agent 交互规范

- 用户看到的是任务结果、证据来源和下一步，不需要理解工作流节点。
- 证据不足时显示“暂未找到可核验内容”，同时提供缩小问题范围的建议。
- 检索失败时显示“数据源暂不可用”，允许重试，不生成具体日期或政策结论。
- AI 回答必须保留来源、状态和追踪信息，便于问题复盘和回归测试。

## 5. 不直接复制的内容

PCIAP 只借鉴 unibestX 的设计组织方式和工程约束，不复制其业务页面、品牌资产、代码实现或具体资源。所有新组件都应符合 PCIAP 的校园信息场景和微信小程序运行边界。

## 6. 页面验收清单

- 首屏是否只有一个清晰主任务？
- 用户是否能在三秒内看懂当前页面用途？
- 加载、空数据、失败和无权限是否都有明确反馈？
- 关键操作是否有成功反馈和失败后的恢复入口？
- 文字、头像和用户身份是否使用统一展示名？
- AI 内容是否标注来源和数据状态？
- 页面是否在窄屏、长标题和无图片时仍保持稳定？
