# PCIAP（民大通）项目 Constitution

## Core Principles

### I. Source-First Campus Information

校园资讯必须保留原文来源、发布时间和可追溯入口。采集失败、来源不明或信息过期时明确提示用户核验，不用旧内容或虚构内容填补页面。

### II. User Action Over Content Volume

产品优先帮助用户回答“与谁有关、什么时候发生、下一步做什么”，页面和 AI 回答围绕行动项组织，避免用更多卡片和按钮制造信息噪声。

### III. Evidence-Bounded AI

Agent 只能基于授权的公开数据和用户明确提交的数据进行检索、解释和编排。缺少证据时必须降级或要求核验，不把模型推测包装成学校官方结论。

### IV. Server-Enforced Permission

游客、普通用户和管理员的权限由服务端和云函数共同校验，客户端隐藏按钮不构成安全边界。敏感数据、密钥、用户标识和管理员能力不得进入公开仓库或模型上下文。

### V. Observable and Testable Delivery

重要 AI 运行记录应包含 traceId、证据数量、审核状态、耗时和重试信息；新增能力必须有页面、云函数或工作流级别的可复现验证，并记录真实限制。

## Quality Gates

- 新页面先明确用户故事、最小操作路径和空态/失败态。
- 新采集器必须保留来源、时间字段、去重和失败状态。
- 新 Agent 节点必须定义输入、工具权限、输出审核和失败降级。
- 发布前分别验证游客、普通用户和管理员路径，并执行 JavaScript 语法和已有工作流测试。

## Governance

本宪章约束后续 Spec Kit 的规范、计划、任务、实现与收敛；不得因追求演示效果而绕过权限、来源核验或失败提示。若与真实代码和测试冲突，以可复现证据为准，并更新制品。
